# 公式工具链与完成判定

> 文档责任：面向后续 coding agent，沉淀公式失败的定位与交付边界。维护义务：区分证据、可复用原则和运行状态；不把设备路径或特定容器镜像变成产品依赖。

## 2026-09-16 教训

成对页面评测中，OmniScientist_fig_1 缺失两处公式，EvoScientist_fig_1 用格式化文本替代数学记号。直接故障是 PATH 中旧 TeX 容器包装脚本优先于可用的本机 TeX Live，包装脚本所需镜像不可用。不是产品要求 Docker，也不是机器没有 TeX。此前把原因概括为 agent 选择容器不够准确。

- 命令存在不等于工具可用。检查实际可执行文件与同名候选；通过现有 `editppt formula render-latex --engine` 指定发现的本机引擎，不优先修改全局环境或拉取无关镜像。
- 分开判断引擎、LaTeX 编译、格式转换、真实 PPT 渲染。SVG 路径失败时可用既有 PNG 路径，但必须保留 LaTeX 来源并检查实际效果。
- 本次本机探针还暴露了第二层故障：默认 `standalone` 的水平盒模式不能直接承载原有显示数学包装，报 `Missing $ inserted`；同一引擎的行内模式成功。运行时改用数学模式内的 `\displaystyle` 保持显示尺寸，必须用真实编译验证，不能只检查可执行文件存在或版本输出。
- 旧 skill 同时要求完整重建、禁止文本拼公式，却允许公式失败后保持 `passed: true`，导致缺失被当成交付警告。公式缺失或未经授权的替代必须保留在 unresolved/missing 对象中，由真实 validator 判失败；结构通过不证明原图内容齐全。
- 不把公式卡片的边框或标题当作公式覆盖证据。每处源公式独立登记并核对实际渲染。不得通过删掉 inventory 或降低预期数量制造通过。
- 公式生成成功也不代表摆放正确。构建器按 `box_px` 拉伸图片，恢复时必须保持资产可见内容的宽高比，以源图字高和基线定位，不能填满卡片导致公式纵向拉长或表格符号过大。
- 标题中的数学符号与原生文本是不同对象；对齐外框顶部不等于对齐可见字形基线。还要匹配源图粗细和间距。worker 自报通过后，仍需对照最终渲染，不能把新的基线偏移笼统归为字体差异。
- 修复已有结果时保留原始失败证据和旧交付物，复用已验证素材，通过公共 CLI 重建并检查最终文件。先检查页面状态：只有 CLI 支持的状态才可 reset；已接受的完成结果用新的 prepare/dispatch 运行恢复，不手改状态或复制旧的通过报告。明确这是定点恢复，不冒充全新端到端评测。
- 字体替换、生成资产细节变化与缺失内容属于不同层级；前两者仍需模型对照源图判断是否可接受，不能笼统归因于 LLM 或用 warning 豁免实质缺失。
