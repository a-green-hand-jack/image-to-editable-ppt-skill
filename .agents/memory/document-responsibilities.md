# 文档责任与个人工作流隔离

> 文档责任：为后续 coding agent 保留本项目的文档边界教训。维护义务：记录可复用的判断规则和纠正依据，不存储私人路径、凭据或易过期的运行状态。不承担产品使用说明。

## 2026-09-16 用户纠正

曾把个人跨设备传输需求、设备绝对路径和私有启动器写进 README、USER、DEV，并把临时试跑状态混入长期文档。这错误地把一次工作委托扩大成了产品契约；仅加一句“开发版提供”或换成路径占位符不能消除这种越界。

## 后续规则

- README 说明产品是什么、完整目标与能力边界；USER 只负责用户安装、使用、观察、恢复；DEV 负责结构、架构、开发目标、验证、发布；AGENTS 负责 coding agent 的开发入口和硬约束。
- 每份新增或修改的文档都应有可见的文档头，说明读者、责任、维护义务和不负责的内容；正文必须符合文档头，不能只加声明而保留越界内容。
- 写入正文前判断信息属于产品能力、通用开发方法、个人工作流还是临时运行证据。只有前两类进入对应公开文档。
- 用户要求某项个人操作，不等于授权把它做成产品功能、安装依赖或公共默认值。私人传输脚本留在开发平面，不写入产品教程，也不因文档清理而擅自删除它。
- 通用路径（如用户目录下的标准安装位置）、仓库相对源码路径和官方公开项目地址可以保留；作者的用户名、设备路径、SSH 别名、私有启动器及具体会话输出路径不能成为公共教程的前提。
- 临时评测状态留在对应运行记录；DEV 描述如何验证，不把一次试跑写成所有用户可复现的产品保证。
- 交付前检查正文是否符合责任声明、是否依赖个人环境、是否夹带运行日志，不能以文档字数减少代替边界检查。
