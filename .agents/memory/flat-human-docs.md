# 扁平且精简的人类文档原则

> 文档责任：面向后续 coding agent，记录本项目的人类文档组织边界。维护义务：保持根目录入口少而清晰，把复杂开发信息放入开发平面。不承担：具体产品流程或某次运行证据。

根目录面向人类的文档应尽可能扁平、少而简洁，同时覆盖产品定位、使用、开发和 agent 入口等必要信息。不要建立专门的 `docs/` 文档系统来层层扩展公开说明；产品流程图等少量公开辅助材料直接放在仓库根目录，并从 README 链接。

详细架构、约束、参考、工作流、脚本、测试和运行证据属于 `.agents/` 开发平面。新增信息前先判断读者：人类只需要稳定入口和必要边界，coding agent 承担大部分操作细节。
